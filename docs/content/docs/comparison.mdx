This page compares oh-my-webbridge 0.2.0 with other tools that give an agent a browser. The facts come from the documentation, release pages and source code of each project, read on 12 November 2026 for the versions in the first table. "Not documented" means that the documentation of the project does not say. To report an error or a newer release, open a [GitHub issue](https://github.com/oh-my-webbridge/oh-my-webbridge/issues). To move an existing setup, see [Migrate to oh-my-webbridge](./migration.mdx).

## Access to a signed-in browser

A tool reaches the browser you use in one of two ways. An extension drives tabs through browser APIs and needs no browser flag. Remote debugging gives the client the whole browser. Chrome 144 and later turn it on for the running browser from `chrome://inspect/#remote-debugging` and ask you to allow the connection. The `--remote-debugging-port` switch requires a profile directory other than the default one ([remote debugging changes](https://developer.chrome.com/blog/remote-debugging-port)).

| Tool                              | Mechanism                                                                         | Setup                                                                                | What the agent can reach                                                                                          |
| --------------------------------- | --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| oh-my-webbridge                   | Extension: `chrome.debugger` in Chrome, WebExtension APIs in Firefox              | Install the extension and enter the code from `omw pair` once                        | Tabs that its sessions open, and the active tab that `find_tab` borrows                                           |
| Kimi browser extension            | Extension with `chrome.debugger`                                                  | Install the daemon and the extension                                                 | Tabs that its sessions open, and the active tab that `find_tab` borrows                                           |
| Browser MCP                       | Extension with `chrome.debugger`, attached only to tabs that an agent uses        | Install the extension and the MCP server, compare a six-digit code once and allow it | Tabs that the agent opens, your tabs that it selects with `tab select`, and tabs that you drag into its tab group |
| Playwright MCP with `--extension` | Extension relay                                                                   | Approve each connection on the connect page, or set `PLAYWRIGHT_MCP_EXTENSION_TOKEN` | Tabs in the tab group of the MCP client                                                                           |
| Playwriter                        | Extension relay                                                                   | Click the extension icon on each tab to control                                      | Every tab with the extension turned on, from every session                                                        |
| OpenCLI                           | Extension with the `debugger` permission                                          | Install the extension                                                                | Tabs in its own tab groups, and tabs that a session binds                                                         |
| Claude in Chrome                  | Extension with the `debugger` permission                                          | Install the extension and sign in with a paid Claude plan                            | Tabs in the tab group of the conversation, and tabs that you add to it                                            |
| Chrome DevTools MCP               | Remote debugging: `--autoConnect` (Chrome 144+), `--browserUrl` or `--wsEndpoint` | Turn on remote debugging and allow the connection                                    | Every window of the profile                                                                                       |
| agent-browser                     | Remote debugging: `--auto-connect` or `--cdp`                                     | Turn on remote debugging and allow the connection                                    | The whole browser; `--pin-tab` binds a session to one tab                                                         |
| PinchTab                          | Remote debugging through `POST /instances/attach`, off by default                 | Turn on attach in the configuration and start Chrome with remote debugging           | The whole browser                                                                                                 |
| browser-use                       | Remote debugging                                                                  | Turn on remote debugging at `chrome://inspect/#remote-debugging`                     | The whole browser                                                                                                 |

## When another tool fits better

- **The agent calls tools only through MCP.** Playwright MCP, Browser MCP, Chrome DevTools MCP, agent-browser, PinchTab and Playwriter run as MCP servers. oh-my-webbridge has no MCP server; an agent runs `omw call` as its skill describes.
- **Windows.** The Kimi browser extension, Playwright MCP, Chrome DevTools MCP, agent-browser, Claude in Chrome and the OpenCLI desktop app support Windows. Playwriter supports WSL, and PinchTab publishes Windows binaries with limited support. oh-my-webbridge runs on macOS and Linux.
- **Microsoft Edge.** The Kimi browser extension, Browser MCP and Playwright MCP with `--extension` work in Edge. oh-my-webbridge supports Chrome and Firefox.
- **Installation from an extension store.** oh-my-webbridge is available from the Chrome Web Store and Firefox Add-ons. Both stores update the browser extension. Install and update the daemon separately. See [Getting started](./getting-started.mdx#install-the-extension).
- **Several browser profiles at once.** One Browser MCP daemon connects up to 8 browsers or Chrome profiles. The oh-my-webbridge daemon accepts one Chrome connection and one Firefox connection.
- **A separate cookie store for each task.** agent-browser sessions, PinchTab profiles, `--isolated` and `isolatedContext` in Playwright MCP, and `isolatedContext` in Chrome DevTools MCP keep cookies apart. All sessions of oh-my-webbridge share the browser profile.
- **No desktop browser**, for example in CI. agent-browser, Playwright MCP, Chrome DevTools MCP and PinchTab start their own browser, headless when needed. oh-my-webbridge needs a running Chrome or Firefox with its extension.
- **Performance, memory and network debugging.** Chrome DevTools MCP records performance traces, runs Lighthouse and reads heap snapshots. Playwright MCP, Chrome DevTools MCP and agent-browser mock network responses.
- **The full Playwright API on your signed-in tabs.** Playwriter runs Playwright code on the tabs on which you turn its extension on.
- **Ready-made commands for popular sites.** OpenCLI ships adapters that return structured data from more than 100 sites.
- **A model in the tool.** Claude in Chrome and the Kimi side panel run a task with their own model. browser-use runs a task with a model that you configure, and Stagehand adds AI steps (`act`, `observe`, `extract`) to a script. oh-my-webbridge carries out the commands of the agent you use and contains no model.
